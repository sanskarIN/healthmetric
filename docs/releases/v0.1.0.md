# HealthMetric v0.1.0 Release Candidate

Status: **prepared, not tagged or published**

This file records the intended first HealthMetric development release candidate. It must not be treated as proof that every platform is production-signed, store-published, or manually validated.

## Version identity

- Git tag when ready: `v0.1.0`
- Android `versionName`: `0.1.0`
- Android `versionCode`: `1`
- Desktop `packageVersion`: `0.1.0`
- iOS `MARKETING_VERSION`: `0.1.0`
- iOS `CURRENT_PROJECT_VERSION`: `1`
- Active preparation branch: `phase3/cross-platform-excellence`
- Release integration pull request: #16

The release-version gate enforces Semantic Versioning and keeps Android, desktop, and iOS user-facing versions aligned. It also keeps the Android and iOS build numbers aligned for this cross-platform release line.

## Intended release scope

### Shared core

- Kotlin Multiplatform adult-only calculation engine.
- Metric and imperial BMI routing.
- Metric and imperial waist-to-height routing.
- Explicit 18+ eligibility boundary in the shared engine.
- Finite-value and plausible-range validation.
- Versioned evidence metadata and neutral educational result language.

### Android

- Compose application with onboarding/adult-use gate, calculators, optional local history, settings, About, and privacy controls.
- History remains disabled by default until explicitly enabled.
- Bounded local retention and defensive JSON backup/restore.
- No application-core Internet permission, Android backup disabled, and cleartext traffic disabled.
- CI-generated debug APK, unsigned release APK, and unsigned release App Bundle.

### Desktop

- Shared Compose Multiplatform UI hosted on Windows, macOS, and Linux.
- Native MSI, DMG, and DEB packaging configuration.
- Repository packages remain beta/unsigned until platform-appropriate signing and manual installation checks are complete.

### Web

- JavaScript and Wasm browser clients using the reusable shared UI.
- Production bundles are build artifacts only until hosting, HTTPS/security headers, browser accessibility checks, and hosting privacy behavior are finalized.

### iOS / iPadOS

- SwiftUI host backed by the shared Kotlin `HealthMetricUI` framework.
- Xcode project generated from `iosApp/project.yml` with XcodeGen.
- Device signing, provisioning, physical-device checks, VoiceOver/Dynamic Type evidence, and TestFlight/App Store distribution remain external release tasks.

## Automated gates required before tagging

The exact commit selected for `v0.1.0` must have successful required checks for:

- standard CI;
- cross-platform clients;
- Android instrumentation;
- Apple shared core and UI;
- Windows/macOS/Linux native desktop packages;
- CodeQL;
- dependency review;
- secret scanning.

The release workflow additionally validates:

- repository invariants and internal Markdown links;
- the tag is a valid `v`-prefixed Semantic Versioning value;
- the tag version matches the configured cross-platform release version;
- Android `versionName`, desktop `packageVersion`, and iOS `MARKETING_VERSION` match;
- Android `versionCode` and iOS `CURRENT_PROJECT_VERSION` match and are positive;
- `CHANGELOG.md` contains the release version section;
- the release version has a version-specific candidate-notes file;
- the changelog release heading has been finalized from `Planned` to a `YYYY-MM-DD` date before a tag can publish;
- shared tests and Kotlin style checks pass;
- Android JVM tests and release lint pass;
- unsigned release APK and App Bundle can be produced.

## Manual gates still required

Before calling `v0.1.0` publicly release-ready for a platform, complete the relevant manual checks in `docs/release.md`, including:

- representative Android emulator/physical-device journeys;
- TalkBack, large text/display scaling, and release screenshots using fictional/example values;
- clean Windows/macOS/Linux installer installation checks;
- representative JavaScript/Wasm browser loading, keyboard, responsive, and screen-reader checks;
- iPhone/iPad simulator and configured physical-device checks;
- VoiceOver and Dynamic Type checks;
- protected Android and Apple signing/provisioning where distribution requires it;
- web hosting, HTTPS, security-header, access-log/privacy, cache, and rollback decisions.

## Distribution statement

Repository-generated Android release artifacts are unsigned. Desktop packages are beta build artifacts. Apple builds are unsigned unless produced in an explicitly configured protected signing environment. Web bundles are static build outputs and are not evidence of a production hosting configuration.

Do not describe any of these as store-published or production-signed until that state is independently completed and verified.

## Tagging rule

Before tagging, replace the `CHANGELOG.md` heading:

```text
## [0.1.0] - Planned
```

with the actual release date in `YYYY-MM-DD` form. Only after the automated gate is green on one stable release commit and the intended platform-specific manual checklist is complete:

```bash
git tag -a v0.1.0 -m "HealthMetric v0.1.0"
git push origin v0.1.0
```

Do not move or rewrite a published release tag to hide a defect. Fix the defect and publish a compatible patch version instead.
